### 1. 免考勤没进"看板"口径——同一件事 5 个出口，只改了 4 个 `✅亲验`

**位置**：`Services/Implementations/AttendanceService.cs:872-900`（`GetTodayStatsAsync`）、`:938-967`（`GetTodayStatsDetailAsync` 的 `notpunched` 名单）、`:1827-1836`（`BuildUserIdQueryAsync`，只过滤 `IsActive`）。
**已改对的 4 处**（对比用）：`Services/BackgroundServices/AttendanceBackgroundService.cs:112`、`AttendanceService.cs:595`（模板报表旷工）、`:835`（月度汇总旷工）、`Services/Implementations/UserService.cs:287`（落库）。

**问题**：看板的总人数和"未打卡"人数都从 `BuildUserIdQueryAsync` 出，而这个方法不认 `IsAttendanceExempt`。免考勤的人（管理员/文员/办公室）不打卡、后台也不给他们建记录，于是：
- **每天都被算进看板"未打卡"卡片**，`NotPunchedCount = 总人数 − 出勤 − 旷工/请假/节假日`；
- **点开"未打卡"下钻名单，里面列着这些人的名字**（跟月度汇总"0 天旷工"的结论互相矛盾）；
- 月度汇总的**应出勤**同样不认这个字段：`CountExpectedWorkdays`（`:1818`）照常按整月算 → 这些人显示"应出勤 22 天 / 出勤 0 天 / **出勤率 0%**"，HR 看就是"一个月一天没来"。

**改法**：给 `BuildUserIdQueryAsync` 加一个 `excludeExempt` 参数，看板与下钻传 `true`；月度汇总对 `IsAttendanceExempt` 直接给 `ExpectedWorkdays = 0`（或干脆不给他生成汇总行）。
**需要你先定一个口径**：看板的**总人数**要不要也排掉免考勤的人？我倾向排掉（看板只反映"需要打卡的人"），但这是业务决定。

## 2. ⚪ 建议先在真 Excel 里点一下确认（1 条）

### 3. 导出表的筛选箭头挂在"合并表头"那一行，列名很可能是空白

**位置**：`Helpers/ExcelExportHelper.cs:220-230`（固定列/尾列在第 2、3 两行**纵向合并**，文字写在合并区左上角即第 2 行）、`:308`（`SetAutoFilter(new CellRangeAddress(3, lastDataRow, …))`，筛选行 = 下标 3 = Excel 第 4 行）。

**问题**：Excel 的下拉框列名取的是**筛选行那一格自己的文字**。固定列/尾列在筛选行上是合并后的空单元格 → "部门""旷工天数"这些下拉框**大概率没有标题**（日号列正常，会显示"1""2""29六"）。HR 想按公告里写的"筛生产部 + 有旷工"就得靠数列数找。现有测试抓不到这一点（只断言了 `autoFilter.@ref`）。

**建议**：打开一份真实导出点几下箭头确认。若确实是空白，最省事的改法是**固定列/尾列不做纵向合并，把列名直接写到筛选行（下标 3）**，让第 3 行成为唯一一行完整表头（第 2 行只留"考勤结果"跨日列）——视觉正常且每格都有名字；改完同步那条"固定列表头纵向合并两行"的测试。

## 3. 🟢 低 / 边角（2 条）

### 4. 设备下班卡比 23:55 那次后台任务晚到 → 记录会一直停在"旷工" `✅亲验`

**位置**：`AttendanceBackgroundService.cs:48-52`（每天只在 23:55-23:59 跑一次）、`:61-68`（补跑条件是"整个窗口都没跑成"，即 `_lastAbsentDate < 昨天`）、`Services/Implementations/ZKDeviceSyncService.cs:227`（下班卡状态白名单是 `Normal/EarlyLeave/NotPunched`，**不含 `Absent`**，这是故意的——旷工只允许被上班卡纠正）。

**问题**：如果 23:55 那次跑成功了，之后（23:57+ 或设备重传延迟）才同步上来当天的下班卡，那天不会再跑第二次；而后台新加的"只有下班卡→记未打卡"分支（`:187-206`）需要"那天再跑一次"才会命中 → 这条记录**停在旷工**，员工第二天来问、要人工补卡。
**改法（一行，语义不变）**：在 `ZKDeviceSyncService.cs:227` 赋值前补
`if (record.ClockInTime is null && record.AttendanceStatus == AttendanceStatus.Absent) record.AttendanceStatus = AttendanceStatus.NotPunched;`
效果与后台那条分支完全一致，但不再依赖"后台有没有再跑一次"。

### 5. 首次打卡"正好等于下班时间"也按下班卡（`>=` 的边界）

**位置**：`AttendanceService.cs:1556-1560` `IsFirstPunchAfterShiftEnd`，判断是 `time >= workDate.ToDateTime(shift.WorkEndTime)`。
**说明**：17:30:00 整的那次唯一打卡会被算成下班卡（当天缺上班卡）。我认为这个方向没问题（判上班会变成"没下班卡"，一样缺卡），但要意识到副作用：**真迟到很久的人（唯一一次卡打在 17:31）会从"迟到 181 分钟"变成"缺上班卡"**，迟到分钟会因此少算。如果 HR 更在意迟到分钟而不是缺卡次数，这条规则要重新商量。取舍，不是 bug。
