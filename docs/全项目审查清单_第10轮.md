**3. 空集合被当成"不限人" → 低权账号可反复触发全公司重算**（维度 1/3/4）`✅亲验`

影响：**没设范围的非 Admin 账号**（`visibleIds == null`）和**范围内没有任何员工的受限管理员**都能触发全公司月度重算；`:71-73` 的注释与本意恰恰是拒绝这类账号做全量重算。`year/month` 还可任意传（2000~2100），可反复刷。属跨分公司写入 + 重负载。
改法：改成 `onlyUserIds is not null` 才限定；或控制器侧 `userIds` 为空时直接返回。

**4. 人脸熔断器被"活体检测成功"清零 → 比对阶段持续故障时熔断永不打开**（维度 1/4）`✅亲验`

问题：两个阶段各自成功后都调 `RecordSuccess()`（把计数清 0），而 `VerifyAsync` 是"活体→比对"串行两次。
影响：只要故障只出在第二步（按接口粒度出故障很常见），每个请求都是"成功清零 + 失败记 1"，计数永远停在 1、到不了阈值 5 → **熔断等于失效**；每次远程打卡跑满重试退避、逼近 `OverallBudgetMs=12000`，熔断的 `LogError` 也永不触发。

**5. 认领退回误伤 → 同一条扫码登记可能建出两个账号**（维度 1/2）`✅亲验`
