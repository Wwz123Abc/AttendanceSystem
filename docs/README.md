# 文档目录

按用途分目录存放，新增文档请放进对应目录；改动文件位置时，同步更新 `README.md`、`CLAUDE.md`、`tools/` 脚本里的路径。

| 目录 | 内容 | 主要读者 |
|---|---|---|
| [`运维/`](运维/) | [部署与交接手册](运维/部署与交接手册.md)（部署流程、回滚、环境现状、踩过的坑）、`agent_ready.sh`（服务器自检脚本） | 开发、运维 |
| [`口径/`](口径/) | [口径登记表](口径/口径登记表.md)：工时、请假、迟到早退、审批等计算规则，每条规则在哪实现、谁拍板的 | 开发、业务 |
| [`变更记录/`](变更记录/) | [更新日志](变更记录/更新日志.md)（按日期，白话）和它的 Word 版；新增记录后要跑 `tools/update_changelog_docx.ps1` 同步 Word | 项目负责人 |
| [`使用说明/`](使用说明/) | [员工操作说明（普通员工版）](使用说明/员工操作说明_普通员工版.md) 及 Word 版，可打印/群发 | 一线员工 |
| [`设计方案/`](设计方案/) | [嵌入管理员 AGENT 实现方案](设计方案/嵌入管理员AGENT_实现方案.md) | 开发 |
| [`审查与验收/`](审查与验收/) | 全项目审查清单、AGENT 验收清单（逐条核实结论与验收记录） | 开发、测试 |

## 约定

- 更新日志只记录用户能感知到的变化，写法见仓库根目录 `CLAUDE.md`。
- 计算口径有改动，先改 `口径/口径登记表.md`，再改代码，并在更新日志里写一条白话说明。
- 审查类文档按"轮次"命名，结论落到口径登记表后，原文只作存档。
