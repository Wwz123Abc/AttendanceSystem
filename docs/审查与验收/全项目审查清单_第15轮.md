**现状**（三处判断都以 `IsShiftWeeklyRestDay` 为唯一口径）：员工当天没有排班记录时，**可以照常打卡**（打卡入口与考勤机同步都不校验有没有排班，`AttendanceService.cs:182-188`），休息日按周六周日兜底（`:1224-1225`），不判迟到/早退，工时按默认标准工时 8 小时封顶（`:2129`），应出勤照算（`:2223`），工作日没打卡仍记旷工（`AttendanceBackgroundService.cs:154`）——即**既被当成"该上班"、又按"没有班次"算**。

**你的口径（2026-10-06）**：期望是"没排班的不应该能打卡"；当天选择**先不改代码**，先查清生产上到底有没有人真的没排班。

**若要改，必须同时改三处**（只堵打卡入口会变成"不让打卡、却照样记旷工"）：① 打卡入口（本地/远程 + 考勤机同步）拒绝并提示；② `MarkAbsentAsync` 跳过无排班的人；③ `CountExpectedWorkdays` 不计无排班的日子。

## 1. 🔴 高（3 条）

### H1. `migrate.sql` 与迁移不同步，缺最新一条 → 用脚本建/升的库，公告功能整片 500 `✅亲验`

`Migrations/` 下共 37 个迁移类，最后一条是 `20260929073129_AddAnnouncementScopeRoles`（给 `Announcement` 加 `ScopeRoles varchar(50)`）；而 **`migrate.sql` 里 `ScopeRoles` 出现 0 次**，脚本最后仍是 `20260928082948_AddAgent`。
EF 把该属性映射进了所有 SELECT（`AnnouncementService.cs:25/44/192`、`Pages/Notice/Publish.cshtml.cs:109`），所以不只是"按角色发布"会炸——**公告栏、发布公告、我发布的列表全部会抛 `Unknown column 'Announcement.ScopeRoles'`**。同时 `__EFMigrationsHistory` 里缺这条，开发环境启动时的 `MigrateAsync()`（`Program.cs:281`）还会再跑一次，两边状态彻底错位。

**改法**：按脚本里既有的 `DROP PROCEDURE IF EXISTS MigrationsScript` 模板，在末尾补 `ALTER TABLE \`Announcement\` ADD \`ScopeRoles\` varchar(50) CHARACTER SET utf8mb4 NULL;` + 往 `__EFMigrationsHistory` 插一行；并加一条"迁移集合比对"的文本断言（见 §6 第 8 条）。

### H2. 安卓壳只声明了 INTERNET 权限 → App 里的"远程打卡"必然失败 `✅亲验`

`mobile-app/android/app/src/main/AndroidManifest.xml:38-41` 只有 `<uses-permission android:name="android.permission.INTERNET" />`。而 `RemotePunch.cshtml:277-280` 用 `navigator.mediaDevices.getUserMedia`、`:229-250` 用 `navigator.geolocation.watchPosition`；Capacitor 的 WebChromeClient 只会去 launch **清单里声明过的** `CAMERA` / `ACCESS_FINE_LOCATION`，没声明时系统立即拒绝——**不是用户拒了弹窗，是弹窗永远不会出现**（随后 `request.deny()` / `callback.invoke(origin,false,false)`）。

**影响**：装了 App 的员工点"打卡"只会看到"未能打开摄像头，请检查浏览器摄像头权限后刷新重试"或"未能获取位置…"，远程打卡（该 App 唯一核心功能）完全不可用，只能改用手机浏览器。
**改法**：补 `android.permission.CAMERA`、`ACCESS_FINE_LOCATION`、`ACCESS_COARSE_LOCATION`；顺带把 `:5` 的 `android:allowBackup="true"` 改成 false 或加 backup rules（避免 WebView 会话数据进云备份）。

### H3. 半天假"上午请假、下午上班、忘打下班卡"→ 工时恒为 0，少发工资 `✅亲验`

`AttendanceService.cs:1409-1418` 只写了"上班卡早于请假段"这一支：`if (record.ClockInTime is { } workedCi && record.ClockOutTime is null) { ... if (workedCi < leaveSegStart) {...} }`。
请假日 08:00–12:00、13:00 打了上班卡、没打下班卡 → 条件不成立 → `ActualWorkHours` 停在 `:1390` 的占位 0，而 `:1386` 照给 0.5 天出勤；两处兜底（`:1556`、`:989`）都要求上下班卡齐全，**月度汇总的自愈也补不回来** → 按工时结算就是少发。

**改法**：补对称分支（请假段结束早于上班卡时，用"标准工时 − 请假小时数"封顶），并纳入月度自愈；补"上午请假、下午打卡、无下班卡"的测试。
