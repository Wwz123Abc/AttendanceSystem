## 1. 项目是什么

面向中小企业的考勤管理系统。ASP.NET Core 8（Razor Pages 为主 + 一小部分 Web API）+ EF Core 9（Pomelo MySQL 驱动）+ MariaDB。核心功能：打卡、请假/补卡/加班/出差审批（多级审批流可配）、排班与考勤组、月度报表导出、后台员工/部门管理。

`README.md` 有基本介绍，但写这份交接文档时 README 已经是拆完钉钉之后重写过的版本，可以信。`CLAUDE.md`（仓库根目录）里有一条**强制约定**：每次功能性改动完成后要在 `docs/更新日志.md` 顶部加一条记录，然后跑 `powershell -ExecutionPolicy Bypass -File tools/update_changelog_docx.ps1` 把 Word 版也重新生成——这个流程必须遵守，不要跳过。

## 3. 这个项目最近经历了一次大重构，脉络是这样的

按时间顺序（也是 `git log` 的顺序），最近这一串改动是**同一条主线**：把打卡数据来源从钉钉切换成熵基（ZKTeco）考勤机，并把钉钉整个拆掉。

1. **`cf02027`** 熵基考勤机 PUSH 协议对接（第一版）：新增 `Controllers/ZKDeviceController.cs`，实现设备侧的 `/iclock/cdata`（握手+数据上传）、`/iclock/getrequest`（心跳，顺便下发命令）、`/iclock/ping`、`/iclock/devicecmd` 这几个写死在设备固件里的路径。当时白名单还是 `appsettings.json` 里的 `ZKDevice:AllowedSerialNumbers` 配置数组。
2. **`9fc8897`** 新建/编辑员工时，把工号+姓名自动推给考勤机（`DATA UPDATE USERINFO` 命令，排进 `ZKDeviceCommand` 队列表，设备下次心跳时取走）。
3. **`dff6b2a`** 白名单从配置文件迁移成数据库表：新增 `ZKDevice` 实体 + "考勤机管理"后台页面，管理员可以直接在页面上增删改设备，不用再改配置文件重启服务。**这是个有意的架构决定**：设备序列号是每台服务器自己的真实硬件数据，不应该写进 `SeedInitialData`/`HasData()`（那是给"总公司"这类所有环境通用默认值用的），每个环境要自己往表里插自己的真实设备。
4. **`65cb622`** 彻底拆除钉钉集成：删掉全部 6 个 DingTalk 客户端、`DingTalkController`、`DingTalkDTOs`、`User.DingTalkUserId`/`Department.DingTalkDeptId` 两个字段（迁移 `RemoveDingTalkColumns`）。**自助"忘记密码"功能也一并下线**（原来靠钉钉工作通知发验证码，代码里没有短信/邮件能力顶替），改成管理员在"员工管理"页面用现成的"重置密码"功能手动处理。这是用户明确要求的范围：钉钉集成"全部拆除"，不是只停打卡同步。
5. **`19a9ec9`** 补上"双向同步"里缺的一半：之前只做了新建/编辑员工推送信息给设备，但员工停用/拉黑/删除/改工号时，设备上的旧记录没有跟着清掉。新增 `DATA DELETE USERINFO` 命令，在 `UserService` 的 `DeactivateUserAsync`/`BlacklistUserAsync`/`DeleteUserAsync`/`SetActiveBatchAsync`（停用分支）/`UpdateUserAsync`（工号变更分支）里都会触发。
6. **`3c7863f`** 修复一个真实 BUG：给考勤机的响应（心跳带的命令、握手配置块等）之前用 `Encoding.ASCII` 编码，命令里的中文姓名被替换成"？？？"。改成设备协议实际用的 GBK 编码。

## 5. 必须知道的坑 / 架构事实（这些不是显而易见的，踩过才知道）

1. **生产环境不会自动建表/改表结构。** `Program.cs` 里 `dbCtx.Database.MigrateAsync()` 只在 `app.Environment.IsDevelopment()` 分支里执行。生产环境（`ASPNETCORE_ENVIRONMENT=Production`）建表/改表全靠部署时手动跑 `migrate.sql`（这个文件是 `dotnet ef migrations script --idempotent -o migrate.sql` 生成的**全量累积脚本**，每次加迁移后都要重新生成，可以安全地在任何历史状态的库上重复执行）。**每次涉及新迁移的部署，忘记跑这一步会导致"表建好了但字段/新表不存在"，应用能跑但一碰新功能就报 SQL 错误。**

2. **MariaDB 全新安装，`root@localhost` 默认是 `auth_socket` 认证插件**，只能本机 CLI 用，.NET 的 `MySqlConnector` 走 TCP 连接会失败。解决办法：建一个专门的应用账号（`caching_sha2_password`），只授权到 `AttendanceDB.*`，连接串用这个账号，不要用 root。wwz.cool 上这个账号叫 `attendance_app`。

3. **GBK 编码坑（.NET Core 默认不认识 GBK）**：`Program.cs` 里有一行 `System.Text.Encoding.RegisterProvider(System.Text.CodePagesEncodingProvider.Instance);`，这是熵基设备协议要求的（协议全程用 GBK，不是 UTF-8）。`ZKDeviceController` 类里有个 `Gbk` 静态字段，**读设备上传的数据、回复给设备的所有响应都必须用这个，不能用 ASCII/UTF-8**——之前就因为回复用了 ASCII，中文姓名被替换成问号（见第 3 节第 6 条）。

4. **请求体读取的隐藏坑**：如果设备的上传请求恰好带了 `Content-Type: application/x-www-form-urlencoded` 之类的表单类型，ASP.NET Core 会在路由匹配后、控制器方法执行前，自己先把请求体当表单读一遍（哪怕参数根本不需要表单数据），导致控制器里手动读 `Request.Body` 时已经是空的——**这个失败模式非常隐蔽：不报错，只是这次上传的数据被无声丢弃**。`Program.cs` 里加了一段只作用于 `/iclock` 路径的早期中间件调用 `Request.EnableBuffering()` 来兜底，`ZKDeviceController.ReadBodyBytesAsync()` 里读之前也会 `Request.Body.Position = 0`。如果以后新增别的设备对接端点，切记也要套这个模式，别重新踩一遍。

5. **打卡数据落库的并发竞态**：`ZKDeviceSyncService.ProcessAttLogAsync` 按"员工+日期"这个组合键（有唯一索引）upsert `AttendanceRecord`。如果设备因网络抖动重发同一条数据，两个几乎同时到达的请求都可能先查到"记录不存在"、都想插入，数据库唯一约束会拦住后到的那个、抛 `DbUpdateException`——**之前的代码是把这个异常吞掉、照样回"OK"给设备，导致这条打卡数据静默丢失**（设备以为传成功了不会重传）。现在的处理方式：`ProcessAttLogAsync` 外层套了个重试（最多3次，遇到 `DbUpdateException` 就 `ChangeTracker.Clear()` 然后重新跑一遍），亲测过真的能触发这个竞态、亲测过重试确实不丢数据。**这个是靠"重新执行一遍幂等的处理逻辑"解决的，不是靠锁——如果以后改这段逻辑，要保证整个方法体重新跑一遍是安全的（不会产生副作用叠加）。**

6. **ZK 设备白名单的语义变了**：迁移到数据库表之后，行为从"白名单为空 = 不限制（开发方便）"变成了"表为空 = 全部拒绝（真正的白名单）"。**任何一次"清空重建数据库"的操作，一定要在重启服务之前先往 `ZKDevice` 表插入真实设备的 SN，不然真实设备的心跳会被拒绝一段时间**（这个已经在 wwz.cool 上真实踩过一次，后来固定成了操作顺序）。

7. **人脸模板不会跨设备同步**——这不是我们代码能解决的问题，是硬件/协议的限制。我们系统只会把**工号+姓名**这些文字信息推给所有已启用设备（`EnqueuePushUserInfoAsync` 循环了 `ZKDevice` 表里所有 `IsActive=true` 的设备），**人脸模板本身是设备本地存储的，录一次只在那台设备上有效**。如果以后要支持多设备人脸互通，需要厂商的集中管理平台（比如 ZKBioSecurity）配合，这块我们还在等熵基技术支持确认（见第 6 节的待跟进事项）。

8. **PUSH 协议的字段细节是"猜"出来的，不是官方完整文档**：手上只有协议目录页（4页，只有封面+TOC）和熵基官方 Java 参考实现（`Demo-Java.zip`，已解压读过 `AttPushProccesor.java`）。`ATTLOG` 的字段顺序（PIN、Time、Status、Verify，制表符分隔）是按这个参考实现 + 实际真机联调验证过的，**基本可信**，但如果换了不同型号/固件的设备，字段顺序未必完全一致，`ZKDeviceController.ParseAttLog` 里有注释标注了这一点，需要调整就改这一个方法，不影响其它部分。

9. **部署工作流程**（已经用了很多次，稳定）：
   ```
   dotnet publish -c Release -o publish
   → 删掉 publish 目录里的本地 appsettings*.json（避免覆盖服务器自己的配置）
   → tar czf publish.tar.gz -C publish .
   → scp 到服务器 /tmp/
   → systemctl stop attendance-net
   → tar xzf 解压覆盖 /var/www/attendance-net/
   → chown -R www-data:www-data /var/www/attendance-net
   → 如果有新迁移：先 mysqldump 备份，再 mysql AttendanceDB < migrate.sql
   → systemctl start attendance-net
   → curl 冒烟测试 + journalctl 看有没有报错
   → 清理服务器和本地的 /tmp 临时文件
   ```
   **任何涉及数据库结构变更（建表/删列）的部署，动手之前必须先 `mysqldump` 备份**（服务器和本地各存一份，本地存在 `db_backups/` 目录，这个目录被 gitignore 排除）。这是用户明确要求的"确保随时能回滚"。

10. **SSH 访问**：私钥 `~/.ssh/attendance_deploy`，`~/.ssh/config` 里已经配好两台服务器的别名（用 IP 而不是域名匹配，`wwz.cool` 要写成 `root@49.232.210.129` 或者显式 `-i ~/.ssh/attendance_deploy` 指定，直接 `ssh root@wwz.cool` 不会自动套用 config 里的身份）。

## 7. 项目里其它值得知道的模块（跟这次重构无关，但接手项目该了解）

- **审批流程**：请假/补卡/加班/出差，支持一级/二级审批（`AttendanceGroup.ApprovalLevel`），审批人配置在"考勤组管理"里。
- **考勤组多打卡地点**：`AttendanceGroupLocation`，支持一个考勤组配多个打卡地点，取最近的算有效范围（`AttendanceService.HaversineMeters`）。
- **员工自助登记**：`Pages/Employee/SelfRegister.cshtml`，扫码填资料，管理员在"员工管理"页面"待确认登记"里审核确认，确认时会顺带触发考勤机同步（走的是同一套 `CreateUserAsync`）。
- **工号自动生成**：按部门找最近的"公司"节点（写死的部门名单在 `UserService.CompanyPrefixByDeptName`），生成"前缀+5位流水号"格式的工号。
- **权限模型**：两条策略，`ManagePolicy`（管理员+文员）、`ApprovePolicy`（管理员+文员+主管+班组长），定义在 `Program.cs`。
